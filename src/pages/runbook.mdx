# If something breaks

Match the symptom to the fix. If you've tried the fix once and it didn't work, **don't keep trying**. Email ThreadCloud Support at [hello@threadcloud.io](mailto:hello@threadcloud.io) with the page you were on, the order or product, and a screenshot.

<div class="callout callout-info">
<div class="callout-title">Last verified against the app: 2026-10-09</div>
If a message here doesn't match the app, it changed and this page is stale. Tell the team.
</div>

<div class="callout callout-tip">
<div class="callout-title">Start with Settings</div>
Most "is it broken?" questions are answered by the store health tiles at the top of <a href="/settings/store-health/">Settings</a>. Open the tile that isn't <strong>Current</strong> and press the one button on its panel.
</div>

## Quick triage

| Symptom | What to do |
|---|---|
| Page is blank or shows an error | Reload once. If every page fails, see [Big failures](#big-failures). |
| A background job looks stuck | **[Stuck background work](#stuck-background-work)** |
| Catalog checking stopped | **[Catalog setup stopped](#catalog-setup-stopped)** |
| Label printer not printing | **[Printer problems](#printer-problems)** |
| Supplier didn't get the PO | **[Resend to the supplier](#resend-to-the-supplier)** |
| Linesheet won't read in Parse &amp; Build | **[Linesheet won't read](#linesheet-wont-read)** |
| Photo upload says "iPhone HEIC photos can't be shown yet. Export as JPEG and add again." | Export the photo as JPEG (on iPhone, share it as JPEG or change the camera format to Most Compatible) and add it again. |
| Shopify says "rate limit exceeded" | Wait a minute and try again. ThreadCloud retries on its own. |
| Merchandising page says "Merchandising access is not enabled for your account" | Ask the account owner to turn it on in [Team access](/settings/users-roles/). |
| A Merchandising figure shows a mark instead of a number | Not an error. Read the reason in the **Notes** at the foot of the page. See [Withheld figures](#withheld-figures). |
| Receiving refuses sizes because a Shopify stock sync is unresolved | **[Shopify stock writes](#shopify-stock-writes)** |
| Wrong size received | **[Fix size](/workflows/receiving/#fix-a-wrong-size)** on the receiving document. Don't unreceive it first; that hides the button. |
| Fixed a size but the document still shows the old one | Expected. A receiving document is a record of that day, not live stock. Check the order's **Receive** tab instead. |
| Catalog publish went wrong | **[Roll back published products](#roll-back-published-products)** |
| Spec sheet reads "Couldn't read" | Try a cleaner PDF or a sharper photo. See [Brand fit](/settings/brand-fit/). |
| Reorder says "Could not verify Shopify cost. Try again." | **[Reorder cost read](#reorder-cost-read)**. Nothing was created. |
| Reorder says "Variant costs differ in Shopify. Review them before reordering." | **[Reorder variant costs](#reorder-variant-costs)** |
| Reorder product reads "Source cost needed" or "has no supplier cost on file" | **[No supplier cost on file](#no-supplier-cost)** |
| "ThreadCloud could not fill every missing Shopify cost. The reorder was still created." | Information only. The reorder is fine. Set the cost on the product in Shopify when convenient. |
| Reorder PO tab shows "Purchase order not issued" | **[Reorder PO not issued](#reorder-po-not-issued)** |
| "Product details could not be opened" or "could not be saved" | **[Product repair from Reorder](#product-repair)** |
| Enrich product reads **Pushed but unverified** | **[Unverified Shopify product](#unverified-product)** |
| Enrich product reads **Not pushed** with "pushing again is fenced" | **[Fenced push](#fenced-push)** |
| Enrich Approve worked but a line under it starts with "Approved." | Not an error. You approved it; ThreadCloud couldn't settle one detail. The line names the reason and the fix. Do what it says, or move on. |
| Enrich bulk buttons are greyed out | A product is mid-save or holding a failed save. Finish it or click **Retry saves**. |
| Supplier says the link reads "This order needs a corrected PO number" | **[No real PO number](#no-po-number)** |
| Supplier says the link reads "This purchase order was revised after this link was sent" | You re-issued the PO. Send them the current link from the PO tab. |
| Supplier says the link reads "This order was revised while you were reviewing it" | Nothing on your side. They reload the page and answer again. |
| Supplier answer says "This review moved on. Reloading." | Someone else changed the answer at the same time. Let it reload, then carry on. |
| A confirmed cost came back red: "currency differs" or "Not applied." | **[Confirmed cost refused](#confirmed-cost-refused)** |
| Applying product details says "would duplicate another product" | Two products would end up with the same supplier reference. Untick or correct the model and colour codes, then apply again. |
| PO sent long ago, no supplier confirmation | **[No supplier confirmation](#no-supplier-confirmation)** |
| Settings shows a **Store reset** row | **[Store reset](#store-reset)** |

## Stuck background work

Reading a linesheet, writing copy, checking the catalog and pushing products all run in the background. The bar at the top of the page shows them working.

<ol class="steps">
  <li>Reload the page. Background work picks up where it left off.</li>
  <li>If it has a <strong>Stop</strong> button, click it, wait for it to stop, then start it again. It only picks up the work that is left, so nothing is done twice.</li>
  <li>Open <a href="/settings/store-health/">Settings</a>. If the <strong>AI engines</strong> tile isn't <strong>Current</strong>, open it and press its button.</li>
  <li>If your AI provider is having an outage, wait 15 minutes and try once more.</li>
  <li>Still stuck: email <a href="mailto:hello@threadcloud.io">hello@threadcloud.io</a> with a screenshot.</li>
</ol>

## Catalog setup stopped

[Catalog setup](/settings/legacy-enrichment/) reads **Checking is stopped**, or says the catalog scan stopped.

<ol class="steps">
  <li>If it says to, press <strong>Check products</strong> or <strong>Scan</strong> to pick it back up. Products already found are kept.</li>
  <li>If some products could not be checked, open the <strong>Problems</strong> tab and read the reason on each.</li>
  <li>If the <strong>Catalog</strong> tile in Settings offers <strong>Run catalog scan again</strong>, press it once. If it refuses, it says why; follow that.</li>
</ol>

## Printer problems

The label printer isn't responding, is out of labels, or jams.

<ol class="steps">
  <li>Check the printer is on, connected, and loaded with the right labels. Print one test label from the printer's own software.</li>
  <li>If your browser blocks the print window, allow pop-ups for ThreadCloud, or open the label from the link the page shows.</li>
  <li>To reprint one label, open <strong>Logistics</strong> and use <strong>Reprint a product label</strong>: scan the barcode or search the product.</li>
  <li>For a whole order, open the order's labels again from receiving. See <a href="/workflows/labels/">Print Labels</a>.</li>
</ol>

## Resend to the supplier

<ol class="steps">
  <li>Open the order, then the <strong>PO</strong> tab.</li>
  <li>Click <strong>Email brand contact</strong> to open a ready-made email, or <strong>Supplier ack link</strong> to copy the supplier's link and send it yourself.</li>
  <li>If you changed the order since sending, use <strong>Re-issue PO</strong> first. The new link replaces the old one; tell the supplier to use the newest email.</li>
</ol>

If **Email brand contact** says there is no brand contact on file, add the order contact on the brand's **People** room in [Brand Registry](/settings/brands-suppliers/).

## Linesheet won't read

Parse &amp; Build can't read the supplier's file, or the read fails.

<ol class="steps">
  <li>Try the same file once more.</li>
  <li>Ask the supplier for a spreadsheet version of the linesheet. Spreadsheets read faster and more reliably than PDFs.</li>
  <li>For a photo, retake it flat and in good light.</li>
  <li>If neither works, add the styles by hand in Parse &amp; Build. Slow, but it always works.</li>
</ol>

## Withheld figures

Merchandising, Stock and Money show a mark instead of a number when the evidence for it isn't complete. That is on purpose: ThreadCloud won't show a number it can't prove.

- Hover the mark, or read the **Notes** (or **Not yet available**) at the foot of the page. Each one says why, and what would clear it.
- Some clear on their own by a date, such as Turns and GMROI on a new store.
- Some need an action, such as setting stock types or costs. Do what it says.
- Don't use a blank as zero, and don't re-label products just to make a figure appear.

## Shopify stock writes

Receiving refuses some sizes with a message that a Shopify stock sync is unresolved. ThreadCloud sent a stock change to Shopify and never got confirmation, so it won't send another for that size until the first is settled.

<ol class="steps">
  <li>Don't re-enter the receipt.</li>
  <li>Open <strong>Settings → Automations</strong>, the <strong>Shopify stock</strong> row. It names the sizes.</li>
  <li>Someone with owner access presses <strong>Read Shopify back</strong>, then checks those sizes in Shopify before entering anything again.</li>
</ol>

The full procedure is on [Shopify stock sync](/workflows/shopify-stock-sync/).

## Roll back published products

You published products from [Catalog setup](/settings/legacy-enrichment/) and the facts are wrong.

<ol class="steps">
  <li>Open <strong>Catalog setup</strong>, then the <strong>Published</strong> tab.</li>
  <li>Tick the products to undo, then <strong>Rollback Selected (N)</strong>.</li>
  <li>Confirm. ThreadCloud restores the values the products had before it published.</li>
</ol>

## Reorder cost read

A new reorder takes its cost from Shopify and won't open on an incomplete cost read. "Could not verify Shopify cost. Try again." means Shopify didn't answer, or answered with an incomplete read. Nothing was created.

<ol class="steps">
  <li>Wait a moment, then pick the product again.</li>
  <li>If it fails three times in a row, check <a href="https://www.shopifystatus.com">Shopify's status page</a>.</li>
  <li>If Shopify is healthy and it still refuses, email <a href="mailto:hello@threadcloud.io">hello@threadcloud.io</a> with the product name. Don't work around it by typing a cost from memory.</li>
</ol>

## Reorder variant costs

"Variant costs differ in Shopify. Review them before reordering." means the sizes of that product carry different costs in Shopify. ThreadCloud won't guess which is right.

<ol class="steps">
  <li>Open the product in Shopify Admin. Check the cost per item on each size.</li>
  <li>Set them to the same figure.</li>
  <li>Pick the product again in Reorder.</li>
</ol>

## No supplier cost

The picked card reads **Source cost needed**, or adding the product says it "has no supplier cost on file".

<ol class="steps">
  <li>From the Reorder search: type the <strong>Unit cost</strong> and its currency, then click <strong>Open reorder</strong>.</li>
  <li>From inside a reorder: set the cost on the product in Shopify (or receive it through ThreadCloud once), then add it.</li>
  <li>A saved list skips these products and names them as left out. Reorder each on its own from the search.</li>
</ol>

## Reorder PO not issued

The PO tab shows **Purchase order not issued** and a reason. Match it:

| Reason | Fix |
|---|---|
| "There is nothing to send. Complete at least one product before issuing this purchase order." | Go back with **Edit reorder** and set at least one size quantity. |
| "This purchase order has already been sent. Open an amendment to revise and re-issue it." | It is issued. To change it, open an amendment, then **Re-issue PO**. |
| "This purchase order cannot be revised because receiving has started." | Expected. Receiving freezes the PO. Place a new reorder for anything extra. |
| "This purchase order was issued by another request. Reload the page to see the current version." | Someone else issued it at the same time. Reload. |
| "N ordered lines cannot be committed" | Those products are missing a fact the supplier needs. **Edit reorder** and fill it in. |

## Product repair

**Edit product details** on a reorder line opens the product for repair. "Product details could not be opened" or "Product details could not be saved" means that hand-off failed.

<ol class="steps">
  <li>Try once more.</li>
  <li>If a field shows <strong>Edit not saved</strong>, enter it again. The save refuses until every unsaved field is entered again.</li>
  <li>If a repair failed earlier, it is on the <strong>Problems</strong> tab of <a href="/settings/legacy-enrichment/">Catalog setup</a> with <strong>Retry repair</strong>.</li>
  <li>Still failing: email <a href="mailto:hello@threadcloud.io">hello@threadcloud.io</a> with the product name.</li>
</ol>

## Unverified product

An Enrich product reads **Pushed but unverified**. Shopify has the product, but at least one ordered size isn't linked to a Shopify variant, so receiving can't book that size.

<ol class="steps">
  <li>Read the line. It names the sizes.</li>
  <li>Click <strong>Push update</strong> on that product (or <strong>Push selected</strong> on several). The push links the missing sizes.</li>
  <li>It should now read <strong>Pushed and verified</strong>. If it reads "This product exists in Shopify. Add sizes before receiving.", the product has no ordered sizes: add them in Parse &amp; Build.</li>
</ol>

## Fenced push

An Enrich product reads **Not pushed**, with a line saying pushing again is fenced. A push may have created the product, but ThreadCloud never heard back. Pushing again could create a duplicate, so it is blocked.

<ol class="steps">
  <li>Click <strong>Verify with Shopify</strong> on that product. It asks Shopify what it has and links it. It never creates a product.</li>
  <li>If it finds one, the line says it found the existing Shopify product and linked it, and that no product was created. Carry on.</li>
  <li>If it finds nothing, the error shows under the button. Check Shopify Admin for a draft with the product's SKU. If there is none, email <a href="mailto:hello@threadcloud.io">hello@threadcloud.io</a> before pushing again.</li>
</ol>

## No PO number

The supplier opens their link and sees "This order needs a corrected PO number." The order has no real PO number, which happens on older orders.

<ol class="steps">
  <li>Open the order. If the PO tab says "This legacy order has no purchase order number. Assign one before issuing it.", assign one.</li>
  <li>Re-issue the PO.</li>
  <li>Send the supplier the new link (<strong>Email brand contact</strong> or <strong>Supplier ack link</strong>).</li>
</ol>

## Confirmed cost refused

On the Supplier answer, a ticked cost came back red instead of green.

| Line reads | Meaning | Fix |
|---|---|---|
| "currency differs" beside the line | The confirmation gives the cost in a currency other than the order's. It is refused, not converted. | Check the document. If the supplier really changed currency, that is a conversation with them, not a tick. |
| A refusal naming a changed order cost | The order's cost moved after you opened the review. | Reload the page and tick again. |
| "Not applied." with no reason | The apply didn't reach that line. | Reload and apply again. If it repeats, email [hello@threadcloud.io](mailto:hello@threadcloud.io). |

## No supplier confirmation

Home's **Needs you** shows **PO sent · no supplier confirmation logged** with **Log confirmation**.

<ol class="steps">
  <li>Check with the supplier that they received the PO. If not, <a href="#resend-to-the-supplier">resend it</a>.</li>
  <li>If they confirmed by email or document rather than through their link, click <strong>Log confirmation</strong> and log it. See <a href="/workflows/supplier-confirmations/">Supplier confirmations</a>.</li>
</ol>

## Store reset

A store reset clears ThreadCloud's records and then the store's products and orders in Shopify. It is only possible on stores ThreadCloud has set up for testing. While one is unfinished, **Settings → Automations** shows a **Store reset** row, and catalog capture, Clean Catalog and Shopify stock writes stand down for the store.

<ol class="steps">
  <li>Leave it while the row has no button. The Shopify part may still be running.</li>
  <li>If the row shows <strong>Resume the reset</strong>, check with ThreadCloud first, then the account owner presses it.</li>
</ol>

<div class="callout callout-danger">
<div class="callout-title">Never press Resume the reset after products were put back</div>
Resume clears whatever is in the store now. If anyone has added products to Shopify since the reset failed, Resume deletes them. Stop and email <a href="mailto:hello@threadcloud.io">hello@threadcloud.io</a> instead.
</div>

## Big failures

These are rare. Don't try to fix them yourself.

| Symptom | What to do |
|---|---|
| Every ThreadCloud page fails | Email [hello@threadcloud.io](mailto:hello@threadcloud.io). ThreadCloud handles it. |
| Linesheet reading and copy fail for 30 minutes or more | Your AI provider may be down. Check [status.anthropic.com](https://status.anthropic.com). Wait; work resumes on its own. |
| Shopify Admin won't load at all | Shopify outage. Check [Shopify's status page](https://www.shopifystatus.com). Wait. |
| A push wrote products with bad data | Don't delete products in Shopify. Email [hello@threadcloud.io](mailto:hello@threadcloud.io) with the order. Fix the source in ThreadCloud and push again once advised. |

## What only the owner should do

Talk to the store owner before you:

- Push more than 200 products at once.
- Change [AI &amp; Pipeline](/settings/ai-models/) writing settings or the AI key.
- Change the [Delivery calendar](/settings/delivery-windows/).
- Publish or roll back catalog facts in [Catalog setup](/settings/legacy-enrichment/).
- Press any recovery button in **Settings → Automations**.
- Use **Reset All**, **Reset windows** or **Reset all suppliers &amp; brands**.

If your finger is hovering over any of those, stop and ask.
