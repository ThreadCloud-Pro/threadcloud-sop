# Parse & Build

Parse & Build is the first tab of every buying order. You drop the supplier's order and everything from the appointment onto one table, press **Parse**, and ThreadCloud reads it into products with sizes, quantities, costs and prices. You check what it built, then send the purchase order and move on to Enrich.

<div class="callout callout-info">
<div class="callout-title">Last verified against the app: 2026-11-13</div>
This screen used to be called Build Order. If a button name here doesn't match what you see, the app changed and this page is stale. Tell the team.
</div>

<div class="callout callout-info">
<div class="callout-title">When to use</div>
Every time you place a new buying order with a supplier. To restock something you already carry, use <a href="/workflows/reorder/">Reorder</a> instead. For a one-off made-to-measure or special order for one customer, use <a href="/workflows/mtm/">Custom orders</a>.
</div>

## What you'll need

- The supplier's order: a PDF, Excel (XLS or XLSX) or CSV linesheet, or photos of a handwritten order
- Any appointment photos: swatch cards, hang tags, garments on the rail
- The brand set up under <a href="/settings/brands-suppliers/">Brands & Suppliers</a>
- Delivery windows set up under <a href="/settings/delivery-windows/">Delivery Windows</a>

## Quick path

<ol class="steps">
  <li><strong>New buying order</strong> on the home screen: answer one question per screen (brand, season, when it arrives), then <strong>Create order</strong>.</li>
  <li><strong>Drop the files</strong> on the table and check each one is marked Order or Context.</li>
  <li><strong>Parse</strong>: ThreadCloud reads the order and the photos into products.</li>
  <li><strong>Check the order</strong>: clear the <strong>to check</strong> notes and place any leftover photos.</li>
  <li><strong>Send PO</strong> to the supplier, then <strong>Enrich for web</strong> to get the products ready for Shopify.</li>
</ol>

## Stage 1: Create the order

On the home screen, the **Merchandising** desk has a tile called <strong>New buying order</strong> ("drop a linesheet · build an order"). Only people with the **Buy** switch see it (see [Team access](/settings/users-roles/)). It opens **New order**, which asks one question per screen. **← Back** goes up a step, and the top right keeps your answers so far.

1. **Which brand?** Type in the **Type a brand** box or pick from **Recent**. If the brand isn't there it says **No brand called "..."** with **Add it**, which opens the Network. A store with no brands reads **Add a brand first**.
2. **Which season?** Pick one of the three that matter now. Each carries a note: **arriving now**, **coming up** or **pre-book**. **No season** (**restocks, MTM**) is for orders that belong to no season. **Another season** (**any year**) opens a year picker with arrows for the previous and next year, then the seasons of that year. A store with no delivery windows reads **Set up delivery windows first**, with **Go to delivery windows**.
3. **When does it arrive?** (**What kind of order?** for a season with no dates.) Pick the delivery window. Each shows its dates, for example "Sep 1 to Oct 31, 2026". Windows that have ended drop off. A second order for the same brand and window shows **next is order 2**.
4. **Create this order?** One sentence names the order: brand, season, window and arrival dates. It also shows the tag the order will use (for example **Tag F6-1**) and **Prices in CAD** with **change** to pick another currency for this order.

Picking a window never creates the order. Only <strong>Create order</strong> does, and it opens Parse & Build. ThreadCloud numbers the PO itself, and the number ends with the order's own id.

If the window is far off, the confirm step says **Receiving starts in N months.** (a plain fact about when the goods are due). If that isn't what you expect, go back and pick the right season, because the season code ends up on the hang tags. If the window has already passed it says **That window has passed. Fine for logging an old order.**

A link from a brand's page or a buying season skips the screens it already answers.

<div class="callout callout-tip">
<div class="callout-title">Filed under the wrong season anyway</div>
Fix it with <a href="/workflows/correct-season/">Correct an order's season</a>.
</div>

## The order header

Every tab of an order (**Parse & Build**, **Enrich**, **Receive**, **Budget**; once the PO is sent, the first tab reads **Purchase order**) shares one slim header:

- The **brand** and **delivery window** as the title.
- The **Delivery** dates, which you can click and edit in place. Click **+ Add dates** if there are none.
- **Order settings**, which opens the order's settings (below).
- On the tab row: **Supplier**, **Currency**, the supplier's confirmation number (**Conf**, or **+ Conf #** to add one) and the supplier **Contact** (or **+ Contact**).

### Order Settings

<strong>Order settings</strong> opens a dialog where you can change the brand, the delivery window, the **Order Currency** (the supplier's invoice currency), the **Supplier Order Reference** (their order or confirmation number, which you can search from the home screen), the **Supplier Contact**, and the **Build view** (**Tiles** or **Grid**). Click <strong>Apply</strong> to save.

## Stage 2: Drop the files

An empty order shows a table that reads "Nothing woven yet. Drop the order and everything from the appointment." You can:

- drag files onto the table,
- drop a whole folder (see below),
- click <strong>Add files</strong>,
- click <strong>Take photos</strong> on a phone or tablet to use the camera, or
- click <strong>Start with one product</strong> to type a product in by hand.

Each file lands on the table as a card, and the table sorts it for you:

- **Order** files become products. A linesheet or an order form goes here.
- **Context** files inform the order but add no products of their own: a fit guide, a price list, a care sheet. They sit on their own **Context** shelf.

Check every card. If a file is in the wrong place, click **Order** or **Context** on its card to flip it. Click the x to remove a file. A file ThreadCloud can't take shows **Not added** with the reason, for example an unsupported file type or an iPhone HEIC photo ("Export as JPEG and add again").

Photos go on the **Photos** pile on the right. Type anything worth knowing in the **Notes** line under the table, for example "Made in Italy. Blue stickers mark the colours ordered."

**Dropping a folder.** You can drag a folder of order files and photos onto the table. ThreadCloud opens it, up to three folders deep and 500 files, sorts what is inside as above, and skips system files such as `.DS_Store` and `Thumbs.db`. If a browser can't open the folder it says **That is a folder. Open it and drop the files inside.**, and you drop the files instead.

<div class="callout callout-tip">
<div class="callout-title">Drop everything at once</div>
A linesheet, a few swatch cards and twenty rail photos can all go in one drop. ThreadCloud reads the sheets first, then the photos, and places each photo on the product it belongs to.
</div>

## Stage 3: Parse

Press the big <strong>Parse</strong> bar under the table.

While it reads, each sheet shows as a card that fills as it goes (**Waiting**, **Reading**, then the number of styles it found). Beside them runs a count of **Styles**, **Units**, cost and **IMU**, and a live line names the sheet it is on. A time estimate appears once two sheets have finished. You can leave the page; the parse keeps running.

To abandon a parse, press <strong>Stop</strong> on the live line. That discards this parse and keeps whatever was already on the order.

Once Parse runs, the notes you typed show as plain text labelled **Sent with this order**. When it finishes, the table shrinks to one band, for example "24 styles woven." with the time, sheets, units, cost and IMU under it, and your products show underneath. Use **+ Add files** on the band to add more later, and **Context** to see the files and notes again.

If a sheet shows **Could not read**, try it once more, then ask the supplier for an Excel or a cleaner PDF. See <a href="/runbook/">If something breaks</a>.

## Stage 4: Check the order

### The "to check" notes

Anything ThreadCloud wants you to look at is gathered in one place: a door on the table that reads, for example, **3 to check**. It opens by itself once the parse finishes if there is something new. Notes you will meet:

| Note | What to do |
|---|---|
| **Not read** | A file could not be read. Try again or add it another way. |
| **Quantities unpicked** or **Quantities still open** | Some quantities did not come through. Type them from the order. |
| **Sizes cleared** | The size run on a product did not add up and was cleared. Re-enter it. |
| **Thread ran short** | The sheet was cut off before the end. Check the last products against the paper. |
| **Fields to review** | The parse was unsure of some fields. Open each named product and check. |
| **Confirm currency** | Check the order currency matches the supplier's invoice. |
| **Without quantities** | These products have no quantities, so a PO cannot carry them yet. |

Click a product in the panel to jump to it. Put a note away once you've dealt with it.

### Photos to place

If some photos did not land on a product, the band reads **N photos to place** (on a phone, **Photos to match**). Click it to open **Match photos**, one screen that goes through every photo still without a product. There is no separate sheet of groups any more.

Each photo comes with a product already picked and the reason in plain words, for example "Burgundy, matches Vino (904)". Press <strong>Enter</strong> to accept it, or pick another product: every product on the order is one tap away, with a **Filter styles** box. The header counts your place ("3 of 20").

The suggestion comes from, in order of strength:

- a care label's fabric and colour code against the codes on the order (a label with an exact code places itself, and the garment shots taken with it follow only on their own agreeing evidence),
- a style code or colour code read from the photo,
- the rest of a burst of the same garment,
- the colour's family, used only when exactly one product on the order is in that family. ThreadCloud never guesses between two products of one family.

Other buttons on the screen:

- **Not a product photo** sets a photo aside: it shows no product.
- **Undo last placement** takes back the last one. **Previous photo** and **Next photo** (or the arrow keys) move without placing.
- **Add to all N**, which appears once you type in **Filter styles**, puts the photo on every product in the filtered list, for a photo that shows the whole range.
- **Re-read** runs the fine print through again on photos with no product identity.
- **Zoom in to check the fine print** lets you pan and zoom on a label before accepting.

When nothing is left, the screen reads **Photos matched** and **Every photo home.**

### The products

Each product shows its article, title, colour, sizes and quantities, cost, MSRP and margin. Switch between **Tiles** (one tile per product) and **Grid** (one spreadsheet-style table per size scale) in <strong>Order settings</strong>. Click a product to open it and fix anything:

| Field | When to fix |
|---|---|
| **Title** | The parse pulled in clutter. Clean it up. |
| **Colour** | The colour name or colour group is off. |
| **Sizes and quantities** | Always check against the paper. This is the most common parse error. |
| **Cost** and **MSRP** | The wrong column was read, or a price is missing. |
| **Stock type** | Tap the badge to change it. |

To add a product the supplier added later, click <strong>+ Add Product</strong>. To move a whole group of products to a different size scale, use that group's size scale control. <strong>Reassign and reset</strong> clears the group's quantities, because the old size columns don't carry over.

**First-draft name.** When Build makes a product and no name is set yet, it saves the name the parse read from the supplier's document (cleaned of brackets and dashes) as a first draft, so the product has a name straight away. Enrich has the final say: it may replace that draft with the customer-facing title. A name you type yourself, or clear on purpose, is never overwritten.

**Supplier reference.** The reference on the PO's **Supplier Ref** column and under each product in the grid is the supplier's own, for example "34 · CF00128/904": the article, the model when it differs, then the supplier's fabric and colour code, or just the colour code ("34 · 904") when there is no fabric code. It no longer prints the internal join of style, model and colour ("34/34/904"). A PO already sent keeps the reference it was sent with.

On a phone, an empty size box shows a grey 0, and the dark bar at the bottom hides while you type so the keyboard has room. It comes back when you finish.

To add a size the product's run doesn't show, click the <strong>+</strong> on its row and type the size.

**Gloves** run 7 to 12 in half sizes (7, 7.5, 8 and so on up to 12), then S, M, L, XL and XXL. Letter sizes always sort after the numbers and in order, S to XXL. A size typed with <strong>+</strong> on a glove product (for example 12 or XXL) saves as a real glove size, so filters and the storefront read it.

**Photos on a product**: in the product's Photos, you can pick up to 5 photos at a time. They upload one after another ("adding 2 of 5"), and the line then reads, for example, "Added 5." If you picked more than 5, it adds the first 5 and says "Pick the rest in another batch." A photo that couldn't be added is named. The same works on Enrich.

<div class="callout callout-warn">
<div class="callout-title">Check the currency</div>
If the order is in EUR but set to CAD, every cost is wrong. The currency sits in the header and in <strong>Order settings</strong>. Check it before you send the PO.
</div>

### Add existing products to the order

When the supplier's order also covers products you already carry in Shopify, add them to the same order so the supplier gets one PO. Click <strong>+ Add existing product</strong> beside <strong>+ Add Product</strong> (it isn't offered on a reorder order). A search opens, titled with the brand ("Reorder -- [brand] Catalog"). Search the brand's products by title or SKU and click one. It lands as a **reorder line**:

- Its sizes follow the live product's variants, so the quantities you type are against the sizes already in Shopify. Its cost fills in only when the product's cost is in the order's currency. On an order in another currency, type the supplier's price.
- On the grid the article field reads **Shopify ref** (your own reference). The supplier's code is its own box, **Supplier code**, typed right in the row. A line with none reads **Supplier code needed** under its title.
- A line that has no photos of its own shows the live product's Shopify photo.
- Beside the line, a note shows how it is doing in the store, for example **On hand 3 · Sold 5 in 13 wks**. It shows nothing for a figure ThreadCloud doesn't have, never a 0.

A reorder line can't go on the PO until it has the supplier's code (**Add the supplier's product code**) and a unit cost (**Unit cost is required before committing to a supplier**). The order's other lines are held to the same rules as before.

You enrich and send it to Shopify with the rest of the order, but the push is a content push into the live product: it adds your tags and writes the line's title, description and SEO text only when the line has copy, and fills a vendor, product type or SEO title only where the live product has none. It never changes the live product's category, stock type, season, price record or variants and never removes anything from it. Receiving then books against the live product's own sizes and blends the new cost into the product's cost. When the supplier's price went up, <strong>Price went up</strong> appears at receiving on that line only. See <a href="/workflows/receiving/">Receiving</a>.

If a line you picked also appears as an ordinary parsed line, the save asks you to remove the parsed line first.

## Stage 5: Send the PO and enrich

Once the order is woven, a footer sticks to the bottom of the page with the style count, units, cost and IMU, and two buttons:

- <strong>Enrich for web</strong>: takes you to the Enrich tab to get the products ready for Shopify. See <a href="/workflows/enrich/">Enrich</a>.
- <strong>Send PO</strong>: opens the purchase order. It stays greyed out until at least one product has an article, a name and a size with a quantity (made-to-order products also need a cost). If some products still have no quantities, a **N without quantities** link sits beside it.

Before either one opens, ThreadCloud may ask you to confirm the size runs.

The purchase order opens on the **Purchase order** tab. Before you issue it, the dark bar at the bottom has one button, <strong>Issue PO</strong>. Click it and pick how the PO goes out:

- <strong>Issue PO &amp; email [brand]</strong>: issues the PO and opens an email to the brand contact with the supplier's answer link. On a computer it opens Gmail; paste the email with Ctrl+V. On a phone it opens the phone's mail app with the draft ready. If the phone asks, tap <strong>Open email draft</strong>.
- <strong>Issue PO &amp; copy answer link</strong>: issues the PO and copies the link the supplier uses to say what they can send. Send it yourself.
- <strong>Issue PO only</strong>: issues the PO and sends nothing. Use this when you will send it yourself later.

The <strong>Share</strong> menu in the header has the same two "Issue PO &amp; ..." items before the PO is issued. There is no way to hand out the answer link without issuing the PO first. That is on purpose, so a supplier never gets a link to a draft.

Also on the page:

- <strong>Copy PO</strong> (in Share): copies the PO as text.
- <strong>Print or PDF</strong> (in Share): prints the PO or saves it as a PDF.

Once the PO is issued, the bar offers <strong>Send to supplier</strong> (the same email as <strong>Email [brand]</strong> in Share) and <strong>Enrich styles</strong>. <strong>Copy supplier answer link</strong> in Share copies the link again. If the PO won't issue, the bar says why.

What happens when the supplier answers, on the same **Purchase order** tab, is on <a href="/workflows/supplier-confirmations/">Supplier confirmations</a>. Every PO, sent or not, is also listed on <a href="/workflows/logistics/">Logistics</a>.

## After the PO is sent

Once the PO is sent, the order is the supplier's size contract and Parse & Build locks. A band reads **PO sent · Build locked**, with:

- <strong>VIEW PO &amp; ACK LINK</strong> to get back to the PO and the supplier link.
- <strong>UNLOCK TO AMEND</strong> to change it. Type a reason (for example "supplier corrected size 48 to 52") and click <strong>UNLOCK</strong>. The band then reads **PO amendment open**. Make your changes and click <strong>PUBLISH REVISION</strong>. Re-issue the PO from the PO page (<strong>Re-issue PO</strong>, with the same three choices as Issue PO) so the supplier gets the new version.

Once receiving has started, the band reads **Received order · Build locked** and ordered sizes are read-only. Fix shipment mistakes from the receipt instead. See <a href="/workflows/receiving/">Receiving</a>.

### Amend on every PO page

Every buying order's **Purchase order** page has an outlined <strong>Amend</strong> button. What it opens depends on where the order stands:

| Where the order is | What you see |
|---|---|
| PO not sent, nothing received | <strong>Amend</strong> opens Parse & Build, still open for changes. |
| PO sent, nothing received | <strong>Amend PO</strong>, the reasoned unlock described above. |
| Anything received | <strong>Amend</strong> opens <strong>Amend a line</strong>. |

In **Amend a line**, pick the line under **Line**, then change its cost, <strong>Retail</strong>, <strong>Title</strong> or <strong>Supplier code</strong>, and click <strong>Save line</strong>. Received sizes and quantities are not changed here: use **Correct** on the receipt (see <a href="/workflows/receiving/#fix-a-wrong-size">Receiving</a>).

- A cost change on a line that was received needs a reason (**Reason for this cost correction (required)**, for example a credit note), and takes an optional **Document reference**. The cost box is called **Net cost**, **List cost** or **Unit cost** depending on the line's discount, and a line under it says what you pay after the discount. **Retail does not follow a cost change on its own.**
- After saving, the page says what happened, for example **Shopify's cost per item updated on 3 sizes.** A new retail or title reaches Shopify on the next push from Enrich. On a sent PO it adds **The supplier's copy of this PO stays as sent.**
- A reorder is corrected in its own reorder workspace, not here.

## Common mistakes

<div class="callout callout-warn">
<div class="callout-title">A context file marked as Order</div>
A fit guide or price list marked Order turns into products of its own. Check each card shows the right role before you press Parse.
</div>

<div class="callout callout-warn">
<div class="callout-title">Wrong size scale</div>
If the supplier ships EU sizes and the product is set to a US scale, the storefront and the hang tags show the wrong sizes. Fix the size scale here, before the first push.
</div>

<div class="callout callout-warn">
<div class="callout-title">Sending a PO with products still to check</div>
The PO only carries products with quantities. Clear the <strong>to check</strong> notes first so nothing is left off.
</div>

## What the system does for you

- Names the PO from the brand and the season.
- Gives each product its SKU before its first push.
- Tags every product with `tc-order-` and the order number, so you can find a whole order in Shopify admin.
- Keeps the exchange rate for the order. It locks the first time you receive.
