# Writing an order

An order is one store's picks from one season's book. You pick in the store, send the buyer a recap to confirm, then send the order to the brand. The brand's confirmation, ship notice and invoice go on the order as they arrive.

<div class="callout-title">Last verified against the app: 2026-11-23</div>
If a button name here doesn't match what you see, the app changed and this page is stale. Tell ThreadCloud.
</div>

## All your orders

On **Today**, the **Orders** row shows how many you have and opens the full list. Each row shows the brand and season, the store, the units and the status. Tap one to open it. With none it reads **No orders yet**. To see one store's orders, open that store: they are under **Orders here**.

## Quick path

<ol class="steps">
  <li>On the store, under <strong>Write an order</strong>, pick the line and press <strong>Open order</strong>.</li>
  <li><strong>Tick</strong> each style the buyer wants, and add sizes, a price or a note.</li>
  <li>Press <strong>Freeze and show message</strong>, then <strong>Copy message</strong>, and send it to the buyer yourself.</li>
  <li>When the buyer confirms, press <strong>Download the order</strong>, press <strong>Email</strong> the brand, attach the file, send it, and press <strong>Mark sent to brand</strong>.</li>
  <li>Add the brand's <strong>confirmation</strong>, <strong>ship notice</strong> and <strong>invoice</strong> as they come in.</li>
</ol>

## Pick in the store

The order page has three tabs across the top: **Order**, **Recap** and **Brand paper**. They stay in view as you scroll. The order page lists the whole book. Each style shows its codes and price.

- **Tap the round tick** to pick a style. Tap it again to unpick it.
- On a picked style, tap **Add sizes, price or a note**. Type the quantity for each size (or one **Qty** when the style has no size run), change **Price each** if the brand agreed a different price, add a **Note**, and press **Save**.
- Once a style has quantities and a price, it shows the units and their total, like **12 units · 2,868.00 EUR**.
- The sizes are a table, not a list. Sizes run across the top with one box under each, and the table scrolls sideways inside the card when the run is long. On a picked style the sizes show as a read-only table with a **Units** total.

Picking copies the book's wholesale price onto the order, so a later linesheet doesn't reprice an order you're already writing. Quantities are whole numbers up to 999 per size.

The header counts what's picked, like **The book 8 picked**, and adds **2 on this phone** while picks wait offline. With no signal, picks are kept on the phone and sent when you're back online (see [With no signal](/reps/#with-no-signal)).

<div class="callout callout-warn">
<div class="callout-title">An order's notes go to the buyer</div>
The <strong>Note</strong> on a picked style is printed in the buyer's recap. Keep private notes on the store page under <strong>Your buyers here</strong>.
</div>

## Scan to order

At an appointment you can find a style by its tag instead of scrolling the book. On the order page, press **Scan a tag**. A sheet opens with the camera.

<ol class="steps">
  <li>Hold the tag in view and press <strong>Scan the tag</strong>. Or type a style code or name under <strong>Or type a code or name</strong>.</li>
  <li>The phone reads a barcode first, then a printed style code. Both are read on the phone, so this works with no signal (see <a href="/reps/#with-no-signal">With no signal</a>). When there is a signal and the phone could not match the tag, ThreadCloud reads it for you as a last step.</li>
  <li>The style opens with its photo, name, code, colour and wholesale price, and one row for each size in its run. Press the plus and minus buttons, or type the number. A size never goes below 0.</li>
  <li>Press <strong>Next</strong> to save and scan the next tag, or <strong>Done</strong> to save and go back to the order.</li>
</ol>

ThreadCloud matches the tag against this season's book, by style code and then model code, ignoring capitals, spaces and dashes. A colour printed on the tag narrows it.

| You see | What it means |
|---|---|
| The style opens | One match. |
| **This code is on more than one colour** | Pick the colour you mean. |
| **Search the book**, with the code filled in | Nothing matched. Search by name or a different part of the code. |
| **This brand's barcodes aren't in the book yet.** | The barcode number matched nothing. Scan the printed style code, or search. |
| **Nothing in this book matches.** | The search found nothing. |

A style saved with every size at 0 still counts as picked, so you can send the recap with or without quantities. If a save does not go through, the sheet says **Did not save. Check the signal and scan it again.** and you can try again.

### The sample is one colour, the style comes in others

The sample on the table is usually one colour. After a scan, the sheet shows the sample's photo, the style name and price, and **Colours in this book** with every colour of that style. The scanned colour is ticked and marked as the sample. Tick the other colours the buyer wants.

If a colour is not in the book yet, add it from its swatch: under **Photograph the swatch with its code showing**, take the photo. ThreadCloud reads the code and name and says **Read from the swatch. Check it before you add.** Check **Colour code** and **Colour name**, fix them if they are wrong, and press **Add colour**. It is added to the season's book with the sample's name, prices and size run. Adding a colour needs a connection, and offline the sheet says so.

Then press **Sizes**, or **Sizes for 3 colours**, and fill the sizes for each ticked colour in turn (**Colour 2 of 3**). **Next colour** saves one and moves to the next.

The swatch photo stays with that colour. It shows on the buyer's confirm page and goes to the store as a swatch (see below).

## Made-to-order pieces

When the brand makes garments to order, the order page lists the pieces instead of the book, with **Add a piece**. Where the brand's form allows it there is also **Made to measure**. Each piece is one garment for one client.

<ol class="steps">
  <li>Press <strong>Add a piece</strong>. Fill in the <strong>Client</strong> where the page asks for one, and pick the <strong>Garment</strong>.</li>
  <li>Pick the <strong>Model</strong> and the <strong>Fabric</strong>, then each option the form lists. Next to <strong>Fabric</strong>, press <strong>Photograph</strong> and take a photo of the fabric label: ThreadCloud reads its code and selects the fabric. Nothing saves by itself, so check what it picked. If the code is not on the form it says so, for example <strong>Read F-123, not on this form</strong>. It needs a signal; typing and picking always work.</li>
  <li>Fill in the <strong>Sizes</strong>, a <strong>Custom detail</strong> if there is one, and the price.</li>
  <li>Press <strong>Add to the order</strong>. Open the piece later to change it with <strong>Save</strong>, or press <strong>Remove from the order</strong>.</li>
</ol>

**A store's usual.** Most pieces for one store repeat the same model and options. Tick **Make this the usual for** the store's name before you save, and the next piece for that store, brand and garment starts from them (**Model and options are the store's usual.**). Fabric, sizes and any option the form marks as picked fresh each time are never copied. **Clear the usual** removes it.

The model's code and version travel with the piece. The brand's order shows the version first, and the store's draft order and its purchase order carry the model code and the option line.

## Send the recap

Under **Send the recap**, press **Freeze and show message**. This freezes the picks as a numbered version (version 1, then 2...) and the order reads **Waiting on the buyer**.

<div class="callout callout-warn">
<div class="callout-title">ThreadCloud doesn't send it for you</div>
The message appears under <strong>Version 1 message</strong>. Press <strong>Copy message</strong> and send it to the buyer yourself, by text, email or WhatsApp. It ends with the link the buyer confirms from.
</div>

The message lists each style with its colour, codes, price, sizes and quantities, and your note, then the total per currency, your name and your agency, and the link. Units with no price are left out of the total, and the message says so.

**Freeze and show message** waits while picks are still on the phone, so a recap never goes out without them.

## The buyer confirms

The link opens a page with the order as you sent it. Each line shows its colour's photo beside it: the colour's own showroom photo, or its swatch when it has nothing else. Above the lines, three figures show the deadline (like **Dec 15**, with the weekday in its label), the units and the total. The buyer types their name and presses **Confirm this order**, or **Ask for changes** and writes what should change. They can't change a quantity or a price: you own every number.

Their answer shows at the top of your order: **Confirmed by** and their name, or **Changes asked by** their name with their note. The order reads **Confirmed** or **Changes asked**.

## Change an order after it was sent

Edit the picks as usual. Any change, even to a note, puts the order back to **Not sent**, and the buyer's old link reads **Your rep is updating this order**. Freeze and send a new recap: the order moves to the next version, and an old link reads **There is a newer version**.

<div class="callout callout-info">
<div class="callout-title">Orders already with the brand keep their status</div>
Changing a pick on an order marked Sent to brand or Brand confirmed keeps that status, and the brand's paper can still be added. The page reads **Changed since the buyer's version** and its number, **Send them a new recap.**, and the buyer's old link reads **Your rep is updating this order** until you do. Change an order the brand already has only when the buyer must confirm the change.
</div>

## Did it reach the store's ThreadCloud?

Once the buyer confirms, ThreadCloud tries to put the order into the store's own ThreadCloud. When it works, the order shows **In the store's ThreadCloud** with **Reached**. When it can't, the order says why in plain words, for example that the store is not on ThreadCloud, or has not switched on orders from reps yet.

When it reaches the store, each colour's real photos come with it. A swatch photo comes marked as a swatch, so the store does not use it as a picture of the garment. Photos made by AI never cross.

Most stores do not use ThreadCloud, so this is normal. The order is still yours and still valid: you send it to the brand as usual. Nothing shows here until the buyer has confirmed.

## Send it to the brand

Once the order has picks, the order page shows **Send to** and the brand's name. It lists the brand's contact person, phone and order email. You set these on the brand's page (see [The brand's contact](/reps/lines-and-seasons/#the-brands-contact)). With no order email it reads **No order email yet** and points you to the brand's page.

Once every pick is saved, you can:

- Press **Download the order** for a spreadsheet of the order for the brand. A style picked with no quantities still has its own row, with the size and quantity blank.
- Press **Email** and the brand's name. Your own mail app opens, addressed to the brand's order email. Attach the downloaded file and send it yourself: ThreadCloud does not send it.

If picks are still saving or waiting on the phone, the page says so and holds these buttons until they are saved.

Then press **Mark sent to brand**. The order reads **Sent to brand**. The button shows while the order is Waiting on the buyer or Confirmed. It only records that the order went.

## Add the brand's paper

Under **Brand paper**, pick **What the brand sent** (**Brand confirmation**, **Ship notice** or **Invoice**), choose the file, and press **Add to the order**. ThreadCloud reads it and keeps the file.

| You add | The order reads | And |
|---|---|---|
| **Brand confirmation** | **Brand confirmed** | ThreadCloud compares it with the version you sent. |
| **Ship notice** | **Shipped** | Your expected commission is recorded (see [Earnings](/reps/earnings/)). |
| **Invoice** | **Invoiced** | Your expected commission is recorded. |

The brand's paper only ever moves an order forward. It can be added once a recap has been sent; before that it reads **Send the buyer a recap before adding the brand's paper.**

### What the brand changed

When the brand's confirmation differs from what you sent, **What the brand changed** lists each difference, for example **size 50: ordered 4, brand has 2** or **250.00 CAD became 260.00 CAD**. Each is marked:

- **Notice**: less than ordered, a dropped style or a lower price. Tell the buyer.
- **Buyer must confirm**: a style the brand added, more than ordered, or a higher price. The page reads **Some of the brand's changes need the buyer's confirmation.** Update the order to match and send them a new recap.

Once the buyer confirms the new recap, each change it took up reads **Buyer confirmed** and the warning goes. A change the new recap left out, or took up only in part, still reads **Buyer must confirm**, and anything left over is listed under **Still to confirm with the buyer**: for example, the brand added two of a style and the recap has one. A style picked with blank quantities or a blank price, or with a price in another currency, has not been agreed to. Fill it in and send another recap.

When nothing differs it reads **The brand confirmed the order as sent.**

## Order statuses

| Status | What it means |
|---|---|
| **Not sent** | Being written, or changed since the last recap. |
| **Waiting on the buyer** | A recap was frozen; waiting for the buyer's answer. |
| **Confirmed** | The buyer confirmed this version. |
| **Changes asked** | The buyer asked for changes. |
| **Sent to brand** | You marked it sent to the brand. |
| **Brand confirmed** | The brand's confirmation was added. |
| **Shipped** | A ship notice was added. |
| **Invoiced** | An invoice was added. |

A shipped or invoiced order can't be changed here.
